## Dowody szczegółowe

### K1

Paczki z `npm pack` (`63fc931` i master `994487e`, oba zbudowane `npm run build`), każda zainstalowana w osobnym konsumencie z `eslint@10.14.0`, `typescript@5.9.2`; `eslint.config.js` = `mielkEslint({ rootDir: import.meta.dirname })`; pliki `src/index.ts`, `scripts/run.ts`, `tools/t.ts` z jednym wywołaniem `console.*`.

```
base (master):  npx eslint .  -> exit 0, brak błędów
chg (zmiana):   npx eslint .  ->
  src/index.ts  1:1 error Unexpected console statement  no-console
  tools/t.ts    1:1 error Unexpected console statement  no-console
  exit 1   (scripts/run.ts bez błędu: domyślne zwolnienie)
```

Przypadek brzegowy: `export const f = (log: Pick<Console,'error'> = console) => log.error('x')` oraz `'console.log(1)'` w tekście i komentarzu w `src/ok.ts` nie dały błędu (zgodnie z README).

### K2

Konsument `chg`, kolejne `eslint.config.js`, wynik `npx eslint .` (pliki z `console`: src, scripts, tools):

| Konfiguracja | Błędy `no-console` w |
|---|---|
| domyślna | `src`, `tools` |
| `allowConsole: ['scripts/**/*.ts']` (jawnie) | `src`, `tools` |
| `allowConsole: []` | `src`, `scripts`, `tools` (3) |
| `allowConsole: ['tools/**/*.ts']` | `src`, `scripts` |
| `allowConsole: ['tools/**/*.ts','src/**/*.ts']` | `scripts` |
| dodatkowy obiekt `{files:['scripts/**/*.ts'], rules:{'no-console':'error'}}` | `src`, `scripts`, `tools` (extra stosowany ostatni) |
| dodatkowy obiekt `{files:['src/**/*.ts'], rules:{'no-console':'off'}}` | `tools` |

README (`63fc931`, sekcja ESLint): opisuje `allowConsole`, domyślne `scripts/**/*.ts`, że poza nimi `no-console` jest błędem, oraz wzorzec `log: Pick<Console, 'error'> = console`. Pusta tablica wyłączająca zwolnienie jest opisana w komentarzu typu `MielkEslintOptions.allowConsole` i w teście jednostkowym; README wprost jej nie wymienia, ale zachowanie zgadza się z opisem „lists the files that may call `console`” (pusta lista = żadne).
